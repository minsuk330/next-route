# 지하철 병목 지도 (#427) — 이벤트 재평가 + 알림이 지하철 2,000 / 6,000 에서 어디서 먼저 깨지나

측정일 2026-10-15. 로컬(앱 한 JVM = api+worker, Postgres·Redis 는 Docker, k6 조회 20 RPS + 여정당 10초 조회).
**지하철 원천은 실제 서울 실시간 도착 API**(프록시 경유, 하루 한도 없음), 여정은 실제 ALL 한 장에서 열차가 있는
(노선, 역, 방향) 키 약 1,350개 위에 임의로 심었다. 발송은 `loadtest` 가짜 발송처(FCM 지연 흉내 평균 60ms).
칸마다 시작 전 지우기·끝난 뒤 남은 진행 중 여정 0·표시 여정 0·토큰 0 을 확인했다. 폴링 대비 전후는 #423 몫이라 돌리지 않았다.
**자원 숫자는 운영 사양과 달라 쓰지 않는다** — 단계 간 상대적 포화 순서를 본다.

## 알림 불변식

| 규모 | 적재(울림/조용) | 경로 버전당 울림 >1 | 번호 중복 | 업무 키 중복 | 적재→발송 p95(보류 포함) | 보류(합치기 창) | relay 지연 p95(예정→발송) |
|---|---|---|---|---|---|---|---|
| 2,000 | 18 / 0 | **0**(가짜 발송처·DB SENT 둘 다) | 0 | 0 | 28.9s(앱 히스토그램 경계 30s) / DB 17.9s | 17.0s | 0.93s |
| 6,000 | 49 / 0 | **0** | 0 | 0 | 28.9s / DB 18.4s | 17.0s | 1.36s |

- 울릴 권리: 2,000 won 18 / 6,000 won 49, 취소·물려받기·반납 0. 조용한 갱신(QUIET)은 한 번도 안 나왔다 — 평가가 밀려 같은 여정이 두 번 악화될 틈이 없었다. **정책의 조용한 경로는 이 사다리에서 검증되지 않음**(가상 모델 회차도 MISSED·재악화 없음).
- 적재→발송 앱 지표는 경계가 0.5/1/2/5/10/30/60초라 p95 가 30초 칸 보간값 — DB 행(보류 17초 + relay 0.9~1.4초)이 정확하다. 보류 17초 = 수집 주기 15초 + 2초(#428 합치기 창, 의도).

## 측정 함정 (재현 시 주의)

- 🔴 **역별 조회 = 전 노선 ALL**: 가짜 공급자로 처음 돌렸을 때 역별 응답이 전부 비었다 — 요청 줄이 `/0/1000/???61`. 한글이 `?` 가 되는 건 로캘이 아니라 Apache HttpClient 5(앱 RestTemplate)다(JDK HttpClient·HttpURLConnection 은 정상). 실제 서울 API 는 이 요청을 ALL 로 답하고, 앱은 받은 3,000행에서 역 id 로 걸러 **값은 맞게** 쓴다 — 그래서 기능 시험으로는 안 드러나고 지연·바이트로만 드러난다. 프록시는 운영처럼 ALL 을 돌려주되 서울 API 를 초당 수십 번 치지 않게 5초마다만 새로 받고 응답은 실측 ALL 지연만큼 쉰다.
- 미룬 키의 기준선을 남기는 설계 때문에 포화 중엔 이벤트÷조회가 1 에 붙는다(위). 이 비율을 "원천이 그만큼 자주 바뀐다"로 읽으면 안 된다 — 원천 변화는 공급자 쪽 기록(키당 분당 약 1회)으로 본다.
- 평가 건수로 센 등급 분포(긴급 80~100%)는 자주 평가되는 긴급이 부풀린 값이다. 심은 비율(긴급 20 / 주의 30 / 여유 50)과 비교할 값은 **변화 시점의 여정 등급**(가상 모델 2,000: 25 / 26 / 46%, 나머지 3% 는 첫 평가 전). 실제 원천 2,000·6,000 은 첫 평가를 못 받은 여정이 76~91% 라 등급 자체를 매길 수 없다.
- 표본기 첫판(역 id LIKE + EXISTS)이 DB 시간 34%(1회 68ms)를 먹었다 → 심은 여정 id 범위로만 거르게 고침(2.1~7ms). 그 회차(가상 r1)는 버림. pg_stat_statements 비중 분모에서 하네스 쿼리는 뺀다.
- 심은 여정의 안내 lease 를 3분으로 두면 relay 가 `lease-expired` 로 알림을 취소한다(앱은 heartbeat 로 늘림) → 3시간으로 심음.
- k6 전이(100초 뒤 걷기 단계)를 끔(`MOVE=false`) — 켜면 준비 시각이 "지금 + 도보"가 돼 전부 긴급.

## 한계

- 노트북 한 대·앱 한 JVM. 6,000 의 DB 수치는 Docker Postgres 한계와 섞임.
- 운영에서 켜진 재탐색 능동 발행·보드(외부 OTP 검색)는 껐다 — 알림 종류는 위험·접근만.
- 역별 조회 프록시는 실측 ALL 지연을 흉내 낸 값(운영 VPS→서울 API 지연과 다를 수 있음). ALL 수집은 실제 왕복.
- 지하철 MISSED 는 생기지 않는다(평가기가 "준비 이후 첫 열차"를 고르므로 여유 ≥ 0). 조용한 갱신 경로는 미검증.
- 실제 원천 회차는 시간대(평일 17~18시) 하나.
