# Phase 8 — 후속 수도권 실시간 공급자 연결

## 작업 계약

먼저 [AGENT-GUIDE.md](AGENT-GUIDE.md)를 읽는다.
선행: P2 ID/시간/coverage 계약. 이 Phase는 별도로 배정된 공급자·지역·수단에 한해 실행한다.
목표: 현재 미지원인 수도권 정적 구간에 검증된 실시간 정보를 연결한다.
기존 실시간 버스·지하철 보존은 P2 책임이며 이 단계까지 미루지 않는다.

## 수행 순서

1. 배정 공급자의 API·키 접근·지원 지역/수단·갱신 주기·쿼터·필드 의미를 공식 명세와 실제 샘플로 확인한다. 공급자가 미정이면 후보/필요 입력만 보고하고 임의의 유료 계약이나 다수 연동을 시작하지 않는다.
2. 현재 port/adapter/cache를 재사용할 수 있는지 확인한다. 정류장 도착예정과 차량 위치를 구분한다.
3. feed/agency/route/stop/trip-pattern occurrence에서 공급자 ID로 이어지는 버전 매핑을 만든다. 번호·역명만으로 확정하지 않는다.
4. 관측시각, 수신시각, 서비스 날짜, 지연/취소/운행없음, horizon/freshness 계약을 정한다. Redis TTL을 데이터 최신성으로 대신하지 않는다.
5. 동일 편 식별이 가능한 결과만 P2 시간축에 합성하고 이후 환승을 재평가한다. 출발편이 불분명하면 정적 결과와 신뢰도 사유를 유지한다.
6. 검증 범위만 기존 coverage 계약에 추가한다. enum 이름은 현재 소비자 호환을 확인하고 확정한다.
7. provider별 공유 cache/동시성 제한을 적용하고 실패 시 가능한 정적 검색을 유지한다. 운행 취소가 확인된 편은 정적 fallback으로 되살리지 않는다.

## 필수 검증

- [ ] stale, 공급자 시간대, 자정 서비스 날짜, 중복 관측.
- [ ] ID 변경/미매핑/동명 노선, 하차역 미정차.
- [ ] API timeout/쿼터/장애, 취소, 미래 출발 horizon 밖.
- [ ] 실시간 대기 중복 없음, 지연 후 환승 가능성 재평가.
- [ ] 해당 provider만 비활성화해도 기존 실시간/정적 검색 유지.

## 완료와 인계

`handoffs/PHASE-8.md`에 공급자/범위, 매핑·freshness 정책, 샘플 fixture, 검증과 fallback 결과, 설정/비용을 기록한다.
검증되지 않은 수도권 전체 지원이나 다른 지역 ML 성능을 주장하지 않는다. 새 ML 학습과 bbox 밖 확장은 별도 작업이다.
