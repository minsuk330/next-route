# 지하철 실시간 — 전 노선 커버리지 (백로그)

작성 2026-09-20. 상태 = **조사 완료, 착수 전**. 최종 목표 = **수도권 모든 지하철 노선에 실시간 정보 제공**.

지금은 구현 계획이 아니라 **실측 기록 + 선택지**다. 착수할 때 이 문서를 근거로 티어를 잡는다.

## 1. 지금 무엇이 되고 있나 (프로덕션 실측)

서울시 열린데이터광장 `realtimeStationArrival` 한 소스로 **19개 노선**이 들어온다.

```
1001~1009(1~9호선) 1032 GTX-A 1063 경의중앙 1065 공항철도 1067 경춘
1075 수인분당 1077 신분당 1081 경강 1092 우이신설 1093 서해 1094 신림
```

**서울시 밖 역도 들어온다.** 문서(`data.seoul.go.kr` OA-12764)에는 "서울시 이외의 역구간은 미제공"이라고
적혀 있지만 실제 수집분은 다르다 — 신창·천안·춘천·문산·광교·연천·소요산 전부 도착정보가 쌓여 있다.
**이 문서 문구를 근거로 판단하지 말 것.** 경계는 행정구역이 아니라 "서울시가 데이터를 받아오는 운영사"다.

## 2. 갭 ① 실시간이 없는 노선 5개 (98역)

| 노선 | 역 수 | 운영사 | 공식 실시간 API |
|---|---|---|---|
| 인천1호선 | 30 | 인천교통공사 | 없음(실시간 *로그* XLSX만 공개) |
| 인천2호선 | 27 | 인천교통공사 | 없음 |
| 김포골드라인 | 10 | 김포골드라인운영 | 없음(2021년 "공개 검토" 답변 후 소식 없음) |
| 의정부경전철 | 16 | 의정부경전철 | 없음 |
| 용인에버라인 | 15 | 용인경량전철 | 없음 |

역 수는 프로덕션 OTP graph 의 패턴별 정류장 실측.

## 3. 갭 ② 19개 노선 안에서 도착정보가 한 번도 안 들어온 역 5개

`1호선 광명·서동탄`(지선 종착), `경의중앙 운천·임진강`(문산 이북), `경춘 광운대`.
지선·저빈도라 수집 창에 안 걸렸을 수도 있다. 5개뿐이라 우선순위 낮음.

## 4. 갭 ③ (별개 축) 검색 자체가 안 되는 구간 — 더 급하다

실시간 이전에 **경로가 안 나오는** 구간이 있다. P1 bbox 필터(west 126.5 / east 127.4)가
"경계 밖 정류장을 하나라도 지나는 trip 은 통째로 제외" 규칙이라 노선 끝이 잘렸다.

| 노선 | 역 마스터 | OTP graph | 잘린 구간 |
|---|---|---|---|
| **공항철도** | 14 | **8** | **인천공항1·2터미널·운서·영종·청라** (검암까지만) |
| 서울1호선 | 102 | 79 | 천안·신창 방면 |
| 경춘선 | 25 | 14 | 춘천 방면 |
| 경의중앙선 | 57 | 47 | 문산 이북 |
| **경강선** | 12 | **0** | 노선 전체 (여주가 bbox 밖) |

**지금 길찾기로 인천공항을 못 간다.** 실시간 도착은 들어오는데 경로가 없다.
이건 외부 API 없이 bbox 조정 + graph 재빌드로 우리가 고칠 수 있다.

## 5. 외부 API 조사 결과 (2026-09-20)

| 소스 | 실시간 도착 | 커버리지 | 판정 |
|---|---|---|---|
| 서울시 TOPIS `realtimeStationArrival` | O | 19개 노선(서울 밖 역 포함) | 현행 |
| 한국철도공사 열차운행정보 | **X** | 보존기간 "1일 전~3개월" = 과거 데이터 | 실시간 아님 |
| 인천광역시 도착정보 조회 | O | **버스 전용** | 지하철 아님 |
| 인천교통공사(data.go.kr) | X | 역사정보 + 실시간 *로그* | API 없음 |
| KRIC 레일포털 오픈API 60종 | X | 시간표·혼잡도(서울교통공사)·공기질 등 정적 | 실시간 도착 없음 |
| KRIC **철도 통합정보 시스템** | **O** | 수도권·부산·대구·광주·대전 통합 | **화면만, 공개 API 아님** |
| TAGO 도시철도(현재 사용) | X | 시간표 | 이미 사용중 |
| ODsay | X | 시간표·경로·노선도 | 실시간 없음 |

핵심: **운영기관을 가로지르는 실시간 데이터는 KRIC 이 이미 통합해 화면으로 뿌리고 있는데 오픈API로는 안 나온다.**

## 6. 선택지

- **A. 시간표 기반 정적 도착 (비용 0, 즉시)** — 미커버 노선을 GTFS 시간표로 채우고 "실시간 아님"으로 라벨.
  재료가 이미 있다: OTP graph 의 GTFS 시간표, TAGO 시간표 어댑터, `OtpLegCoverageResolver` 의
  `REALTIME_CAPABLE` / `STATIC_SCHEDULE` 구분. "정보 없음"을 "정시 기준"으로 바꾸는 것.
- **B. KRIC 통합정보 스크래핑** — 커버리지 최대(수도권+지방 4대 도시). 비공개 엔드포인트라
  약관·차단·스키마 변동 리스크. 쓰려면 엔드포인트 안정성 스파이크가 선행.
- **C. 운영기관 개별 제휴** — 인천교통공사·김포골드라인운영 직접 문의. 공식이지만 리드타임 길고
  기관마다 포맷이 다르다.

## 7. 제안 순서

1. **갭 ③ 먼저** (bbox·graph, 외부 의존 0). 체감이 가장 크다 — 인천공항·경강선이 검색에서 통째로 빠져 있다.
2. **A** 로 갭 ①을 정직하게 메운다(정적 라벨). 실시간 없는 구간이 "빈 화면"이 되지 않게.
3. **B 스파이크**로 진짜 실시간 가능성 판정 → 되면 갭 ① 실시간 전환, 안 되면 **C** 로 장기 진행.

## 8. 재현 명령

```bash
# 실시간이 실제로 들어온 노선/역 (VPS)
psql -c "select line_id, count(distinct station_id) from subway_arrival_raw group by 1 order by 1;"
# 역 마스터 대비 커버리지
psql -c "select s.line_id, count(distinct s.statn_id) master, count(distinct a.station_id) covered
         from subway_station s left join (select distinct line_id, station_id from subway_arrival_raw) a
         on a.station_id=s.statn_id and a.line_id=s.line_id group by 1 order by 1;"
# OTP graph 의 지하철 노선·정류장 (VPS, nextroute_default 네트워크)
docker run --rm --network nextroute_default curlimages/curl -s -X POST \
  http://otp:8080/otp/routers/default/index/graphql -H 'Content-Type: application/json' \
  -d '{"query":"{ routes(transportModes:[SUBWAY]) { shortName patterns { stops { name } } } }"}'
```
