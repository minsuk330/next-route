# 역 출구를 OTP 그래프에 넣기

## 뭘 하나
GTFS 에 역 묶음·출구(OSM 4,462개)·승강장↔출구 통로를 추가해 그래프를 다시 만들고, 검색 좌표가 지하철 승강장 근처면 역 ID 로 검색한다.
역에서 출발·도착할 때 네이버처럼 가장 가까운 출구에서 걷게 된다.

## 왜
출발·도착이 역 안의 한 점이라 출구 옆 버스정류장까지 도보가 10~20분으로 잡혀 직통 버스(잠실→강남 360·2000)가 빠진다.

## 핵심 결정
- 출구는 GTFS 출구+통로로 넣음 — OTP 는 통로가 있어야 승강장과 출구를 잇는다. OSM 출구 자동 연결은 경로에 안 쓰여 기각
- 역 판별은 서버에서(승강장 80m 안) — 앱 계약 불변. 앱이 역 ID 보내기는 기각(앱 수정 필요)
- 같은 역 승강장끼리 통로 = 기존 환승 최소시간 — 출구 경유로 환승이 나빠지지 않게
- 출구가 없는 역은 통로 없이 그대로 — 승강장 고립 방지
- 3단계 PR: 전처리 도구 → 앱 역 판별 → 그래프 재빌드·배포

## 건드는 곳
tools/transit-routing-benchmark/runner(add_station_entrances.py 신규, build_otp_graph.sh), OtpRoutingAdapter, OtpStationResolver(신규), OtpRoutingProperties, OtpPlanConnectionMapper, LegacyRouteResponseMapper, 테스트

## 리스크
- 출구 좌표·매칭이 틀린 역은 통로 때문에 오히려 접근이 나빠질 수 있음
- 응답이 도보 없이 대중교통으로 바로 시작할 수 있어 앱 표시 확인 필요
- 그래프 재빌드·OTP 재시작(배포 포크 jar 필수, 캘린더 11-30 만료 별건)
