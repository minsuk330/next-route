# H-only shared-graph experiment result

Updated 2026-09-15. This is the result of executing
`H-ONLY-SHARED-GRAPH-AGENT-PLAN.md` against upstream OTP `dev-2.x` commit
`a0b62f69fc543e84687752e17dae8a66b01c5e28`. It uses only the H change in
`TripPatternForDates`; the historical H+F commit was not used.

## Conclusion

**Final classification: `ALLOCATION_REDUCTION_ONLY`; latency: no improvement; RSS: no
reduction demonstrated.**

The strongest result is semantic equivalence on one serialized graph: all 12 fresh-JVM runs
(six A/H pairs) produced byte-for-byte identical result CSVs, including itinerary fields and
`c1`/`c2` costs. The official expected file has 233/408 matching cases for both variants;
the remaining 175 are expected-file mismatches, not a claim that 175 searches failed.

JFR's sampling estimator supports lower allocation pressure for H, especially the temporary
`int[]` and `TripPatternForDates` constructor allocation. This is not the same as retained
heap or RSS reduction. The sampled whole-process RSS was effectively unchanged, and the
primary Routing Total mean was slightly slower for H with a confidence interval crossing zero.
Therefore a PR may claim allocation-pressure reduction and preserved results, but should not
claim a speed or process-memory win from this local experiment.

## Correctness gate

The 12 result files each contain 1,207 data rows and have the same SHA-256:
`f417493103bba636a2ab69f06c1042e7cadf08b0ebc9498334d5b0ff96f41b43`.
An independent CSV comparison found zero differences in `tcId`, transfers, start/end times,
`c1`, `c2`, duration, agencies, modes, routes, stops, or details; per-testcase itinerary
multisets also matched. Every process exited 0 and reported 233/408 official expected matches.
The official expected mismatch count was identical for A and H in all runs.

## Performance and RSS

Run representatives are the mean of the four official SpeedTest samples. Case percentiles are
computed from the final sample's 408 `Total times(ms)` values using median for p50 and the
nearest-rank 95th percentile. Improvement is `100 × (A − H) / A`; positive means H is lower.

| Metric | A mean | H mean | Mean paired change | 10,000-resample paired bootstrap 95% CI for change |
| --- | ---: | ---: | ---: | ---: |
| Worker/RAPTOR mean | 51.29 ms | 55.17 ms | −7.63% | [−10.33%, −4.92%] |
| Routing Total mean (primary) | 93.42 ms | 94.63 ms | −1.35% | [−3.58%, +1.03%] |
| Case Total p50 | 80.17 ms | 81.83 ms | −2.09% | [−5.93%, +0.30%] |
| Case Total p95 | 173.50 ms | 194.17 ms | −12.04% | [−23.98%, −4.37%] |
| Sampled peak RSS (whole process) | 5,220,544 KiB | 5,250,784 KiB | −0.99% | [−7.43%, +3.67%] |
| Sampled RSS median | 3,479,420 KiB | 3,498,107 KiB | −0.58% | [−2.47%, +1.40%] |

RSS was sampled from the actual JVM PID at roughly 0.5-second intervals; run sample counts
were 286–309 and the largest interval was 697 ms. It is a sampled whole-process peak, including
graph residency, not a routing-only allocation measurement. All recorded `Swapins` and
`Swapouts` deltas were zero. The primary Total CI is below the exploratory +5% non-inferiority
bound, but its upper bound is above zero; this is evidence of no material regression within
that bound, not evidence of a speedup. Worker/RAPTOR was slower for H in all six pairs.

## JFR allocation, heap, and GC diagnosis

Four fresh JVMs used the same graph, flags, SpeedTest arguments, and JFR `profile` settings.
The recordings were not included in the S4 latency averages. `ObjectAllocationSample.weight`
is a sampling estimate over the full recording (startup, graph load, warmup, and measured
routing); it is not exact allocated bytes or retained heap.

| JFR aggregate | A (two recordings) | H (two recordings) | H relative to A |
| --- | ---: | ---: | ---: |
| Weighted allocation estimate per recording | 170.022 GB | 150.691 GB | −11.37% |
| `int[]` weighted estimate per recording | 22.326 GB (13.13% pressure) | 3.608 GB (2.39%) | −83.84% |
| Top-frame `TripPatternForDates.<init>` estimate | 19.904 GB (11.71%) | 1.080 GB (0.72%) | −94.57% |
| After-GC live heap median | 949.8 MiB | 945.1 MiB | −0.49% |
| Natural G1 GC events per recording | 113 | 109 | diagnostic only |

The two pair-level total-allocation reductions were 11.48% and 11.26%; the corresponding
`int[]` reductions were 82.74% and 84.87%. This is consistent with the H design avoiding the
request-local arrival/departure arrays. It does not prove that the removed arrays are the only
allocation in the constructor, nor does it imply an RSS reduction. GC pause totals were
1,664.6/1,680.0 ms for A and 1,540.9/1,616.8 ms for H; maximum pauses were
209.4/221.9 ms for A and 195.2/208.3 ms for H. These are diagnostic observations from only
two pairs, not a separate significance claim.
