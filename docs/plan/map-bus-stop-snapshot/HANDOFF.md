# 모바일 인계 — 지도 버스정류장 스냅샷

## 요약

정류장 마커용으로 `/api/nearby/bus-stops` 를 **더 이상 호출하지 않는다**. 서울 전체 정류장을
앱 시작에 한 번 받아 로컬에 두고, 지도 팬/줌에는 네트워크를 쓰지 않는다.

**서버 변경만으로는 끊김이 다 없어지지 않는다.** 아래 클라 4항목이 남은 절반이다.

## 엔드포인트

```
GET /api/map/bus-stops/snapshot
If-None-Match: "12986-1786000000"     (저장해 둔 version, 선택)
```

인증 불필요.

### 200

```json
{
  "version": "12986-1786000000",
  "count": 12986,
  "columns": ["stopId", "arsId", "stopName", "lat", "lng"],
  "stops": [
    ["100000001", "01001", "종로2가사거리", 37.56981, 126.98775]
  ]
}
```

- `stops` 는 배열의 배열. 열 순서는 `columns` 가 정의한다 — 인덱스를 하드코딩하지 말고
  `columns` 로 한 번 검증할 것 (열이 추가되면 뒤에 붙는다).
- `arsId` 는 **null 일 수 있다** (안내단말기 없는 정류장). 빈 문자열이 아니라 null 이다.
- 좌표는 소수 5자리(≈1.1m).
- 실측 크기: raw 약 940 kB, **gzip 약 233 kB** (2026-08-19, 12,986행). `Accept-Encoding: gzip` 필수.
- 응답 헤더: `ETag: "<version>"`, `Cache-Control: public, max-age=3600, must-revalidate`.

### 304

`If-None-Match` 가 현재 버전과 같으면 본문 없이 `304`. 로컬 저장분을 그대로 쓰면 된다.
(`W/"..."` weak 형식도 허용)

## 클라가 해야 하는 것 (이게 끊김의 나머지 절반)

### 1. 마커 upsert — clear-and-redraw 금지

카메라 이벤트마다 마커를 지우고 다시 만들면 데이터가 로컬에 있어도 깜빡인다.

- `stopId` → `Marker` 맵을 유지하고, 보이기/숨기기는 `marker.map = null / naverMap` 으로 토글
- `new Marker()` 를 카메라 이벤트마다 만들지 말 것 (객체 재사용)
- 화면 + 패딩(1.5배) 밖으로 나간 것만 숨긴다

### 2. 그리드 셀 인덱스

- 셀 크기 0.005°(≈500m) 기준으로 `floor(lat/0.005), floor(lng/0.005)` → 셀 키
- 셀 키 → `stopId` 목록 해시맵을 앱 시작에 1회 구축
- 카메라 idle 에서 화면 bbox 와 겹치는 셀만 꺼내 렌더. 매번 12,986개를 훑지 말 것

### 3. 줌 게이팅 / 클러스터 (성능상 필수)

12,986개 마커를 동시에 올리면 프레임이 죽는다 — 끊김이 "마커 사라짐"에서 "버벅임"으로 바뀔 뿐.

- 임계 줌 아래에서는 개별 정류장을 숨기거나 클러스터로 대체
- 안드로이드: 네이버 SDK 클러스터링 유틸(`Clusterer`) 지원 버전인지 먼저 확인
- iOS: 대응 API 없으면 2번 그리드 셀로 직접 묶어 대표 마커 1개
- 임계 줌 값과 셀 크기는 **실기기 프레임 보고** 정한다. 서버 테스트로는 판정 불가

### 4. 초기 로딩 — 번들 + 백그라운드 파싱

- 첫 실행에 233 kB 를 받아 파싱·인덱싱하기 전까지 마커가 0개다. 스냅샷 JSON 을 **앱 에셋으로
  번들해서 출시**하고, 시작 후 `If-None-Match` 로 갱신만 하는 것을 권장
- 파싱·인덱스 구축은 **메인 스레드 밖에서**. 12,986행 파싱을 UI 스레드에서 하면 실행 직후 프리즈
- 로컬 영속화(파일 또는 SQLite) + `version` 함께 저장. 다음 실행에 그 값을 `If-None-Match` 로 보냄

## 갱신 정책

정류장 표는 거의 변하지 않는다. 앱 시작 1회 재검증으로 충분하다.
지도 화면 진입마다 재검증하지 말 것 (304 라도 왕복은 왕복이다).

## 도착정보는 분리

마커는 정적 데이터, 도착정보는 마커 탭 시 기존 arrival API 단건 조회. 스냅샷에 실시간 정보는 없다.

## 계속 쓰는 API

`/api/nearby/bus-stops` 는 검색·resolve 경로에서 그대로 유지된다. 지도 마커용으로만 쓰지 않는다.
