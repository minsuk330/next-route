# 여정 체크포인트 정책 (Phase 5 ④, L)

> codex 설계 리뷰 반영 완료(2026-08-10). 지적 7개의 처분은 [PLAN.md](./PLAN.md) §13,
> 구현하며 뒤집힌 결정 하나는 §2.2. 선행 PR #127 위에서 이어진다.

## 뭘 하나

"갈아탈 차가 곧 온다"는 알림(N2) 하나를 새로 만든다. 사용자가 환승 정류장에서 기다리는 중이고
버스가 2분 안에 오고 아직 위험 알림이 안 나간 상태일 때 한 번 나간다. 마이그레이션 없음.
운영 발송은 이 PR 도 켜지 않는다 — ⑤·⑥ 뒤에 켠다.

## 왜

②가 "나빠질 때만 알린다"(N6·N7)를 이미 구현했다. 남은 서버 소유 요구사항 중 알릴 순간이
따로 있는 것은 N2 하나다.

## 핵심 결정

- **체크포인트를 3개에서 멈춘다.** N4·N5·N8 은 사건이 아니라 알림을 열었을 때 볼 내용이라 ⑥ payload
  소유다. 요구사항 ID 1:1 매핑은 기각 — 소음만 는다
- **하차·정류장 접근(N1·N3)은 어휘에 아예 없다.** 규칙이 아니라 타입으로 막는다
- **취소 규칙을 비대칭으로 나눈다.** 회복에서는 N2 를 보호하고, 승격에서는 아직 안 나간 N2 만
  취소한다. 바뀌는 쿼리는 회복 하나뿐이고, 그 필터는 정상 전이에서 발동하지 않는 **불변식 가드**다
- **배타성의 축을 상태가 아니라 단계로 둔다.** 정류장에 서 있으면 여유 = 남은 시간이라, 차가 창
  (2분) 안에 오면 상태는 거의 항상 `AT_RISK` 다 — "안전 상태에서만 알린다"는 처음 규칙은 스스로를
  배제했다. 그 자리에서 `AT_RISK` 는 위험이 아니라 탈 준비 신호이므로, **대기 단계에서는 위험
  알림이 자리를 넘기고 접근 알림만 나간다**(`MISSED` 는 넘기지 않는다)
- **채널 결정 조건을 함께 넓힌다.** 지금은 위험 상태에서만 발송 정보를 만들어, 이걸 빼면 코드가 다
  있어도 N2 가 **한 건도 안 나간다**(codex 가 잡은 최우선 구멍). 판정은 새 policy 하나가 소유해
  평가 서비스와 판정기가 같은 조건을 본다
- **억제는 키만, 만료에 바닥 없음.** 마커 컬럼을 안 만들어 마이그레이션을 피하고, 버스가 떠난 뒤의
  "곧 온다"는 못 보내면 버린다
- **relay 를 깨우는 기준은 "행이 실제로 생겼을 때"다.** 중복 틱마다 깨우면 임박 창 동안 헛수고가 는다

## 리스크

- **승격 뒤에도 이미 claim 된 N2 는 나간다.** 발송 직전 재확인이 여정·revision·만료만 보기 때문이다.
  창이 좁아 수용하고, 최신 환승 상태 확인은 ⑤ 로 넘긴다(PHASE-5 ⑤ 절에 명시)
- **N2 는 환승당 평생 1회.** 승격에 취소되면 상태가 회복돼도 다시 안 나간다(수용)
- supersede 가 갈래 둘이 된다. 필터를 반대쪽에 붙이면 회복이 아무것도 안 지운다 — 검증 8·9 가 방어선
