# 역 도착 응답에 방금 떠난 열차 추가 (#299)

## 뭘 하나
`GET /api/subway/stations/{stationId}/arrivals` 의 방향마다 `departed`(이 역을 떠난 열차, 최근 순 최대 3대·10분 이내)를 싣는다.
열차 번호·행선지·종류·떠난 시각·지금 위치를 준다.

## 왜
사용자는 대개 타고 나서 앱을 연다 — 자기 열차는 이미 떠난 쪽에 있는데 서버가 그걸 안 줬다.

## 핵심 결정
- 새 버퍼를 만들지 않는다: 위치 수집기(M7)가 이미 Redis 에 출발 사건을 15분 쌓고 있다(이슈 전제 정정)
- 탑승 판정과 같은 조회를 써서 `trainNo` 가 열차 선택(#293)과 맞는다
- 떠난 시각 = 관측 구간 가운데(원천 해상도 60~150초)
- 출발 로그를 못 읽으면 떠난 열차만 비우고 곧 오는 열차는 그대로

## 건드는 곳
SubwayStationArrivalQueryService, SubwayStationArrivalsResponse, HANDOFF.md(모바일)

## 리스크
- 위치 원천이 없는 6개 노선(경의중앙·경춘·수인분당·경강·서해·신림)은 늘 빈 목록

## 검증법
서비스 테스트(최근 순 3대·10분 창, 행선지·종류·위치, 로그 실패, 서비스일 경계) + 컨트롤러 JSON 통과. 배포 후 강남 2호선·신분당선 실호출.
