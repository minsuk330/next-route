# M7 PR-4 지하철 탑승 열차 매칭기

## 뭘 하나
쌓아만 두던 두 재료 — 앱이 보낸 탑승 관측(PR-3)과 실시간 열차 출발·도착 로그(PR-2) — 를 맞춰
"이 사람이 탄 열차"를 실제로 고른다. 상태가 `PENDING` → `PROVISIONAL` → `CONFIRMED` 로 올라간다.
지금은 판정기가 없어 관측이 아무리 쌓여도 영원히 `PENDING` 이다.

## 왜
서버는 모든 열차 위치를 알고 폰은 탔다는 것만 안다. 터널에서 GPS 가 죽으므로 좌표 비교가 아니라
탑승 순간에 둘을 한 번 이어야 한다. 이 PR 이 그 잇는 자리다.

## 핵심 결정
- **PR-4a(매칭기)/PR-4b(수명주기) 로 쪼갠다** — 4a 는 신규 파일 위주라 순수 단위 시험으로 끝나고, 4b 는 기존 서비스 4개를 건드려 회귀 위험 축이 다르다. 푸시 알림은 둘 다에서 빼고 PR-5 가 전담한다
- **확정은 "같은 역에서" 잰다** — 후보들의 다음 역 도착 시각을 비교하되, 비교역이 갈리면 확정하지 않는다. 역을 안 맞추고 비교하면 앞차의 두 정거장 뒤 도착과 뒷차의 한 정거장 뒤 도착이 겹쳐 엉뚱한 열차가 1등이 된다
- **낡은 근거로 한 판정을 막는다** — 관측 수신은 순번만 올리고 버전은 안 올리므로, 조건부 갱신에 순번까지 넣는다. 여정 종료와의 경합은 쓰기 직전 세션 행을 다시 잡아 순서를 정한다
- **재탐색 때 잠정 상태도 근거째 새 단계로 옮긴다** — 안 옮기면 이동 시작 관측이 다시 오지 않아 그 여정은 남은 내내 "확인 중"에 갇힌다. 단 구간이 완전히 같을 때만
- **애매하면 고정하지 않는다** — 후보 한 대여도 자동 확정 금지, 급행 배제, 기기 시계가 수상하면 관문을 더 좁힌다. 종착역으로 후보를 거르는 것도 **뺐다** — 잘못 거르면 후보가 줄어 오히려 잘못 고정 쪽으로 기운다
- **판정기는 전부 네이티브 조건부 갱신으로 쓴다** — JPA 자동 갱신과 섞으면 버전이 두 번 올라 늦게 온 갱신이 되살아난다

## 리스크
- **관문 숫자에 근거가 없다** — 실기기 관측 전이라 전부 잠정값. 그래서 전부 설정값이고 기본 off 다. 사유별 지표를 같이 넣어 나중에 조인다
- **방향 검증을 엄격하게 바꾸면 기존 대기 ETA 경로도 같이 바뀐다** — 회귀 시험 필수. 허용값이 노선별로 달라(2호선만 다름) 하나로 묶으면 하행이 통째로 죽는다
- **스캔 질의가 이 PR 최대의 사고 경로** — 세션·개정본 조건을 빠뜨리면 끝난 여정을 영원히 재처리하고, 판정 불가 행을 안 빼면 오래된 50건이 배치를 독점해 뒤가 굶는다
- 마이그레이션 없음. V44·V45 가 이미 필요한 칸을 전부 들고 있다
