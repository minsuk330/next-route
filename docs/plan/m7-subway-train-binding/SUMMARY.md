# M7 지하철 탑승 열차 자동 판정 (백엔드)

## 뭘 하나
아이폰이 "차량 이동 시작"을 알려주면, 서버가 그 시각에 탑승역을 실제로 출발한 열차를 찾아
여정을 **그 열차 하나에 고정**한다. 고정 뒤에는 그 열차의 실시간 위치만으로 Dynamic Island를 갱신한다.

## 왜
서버는 모든 열차 위치를 알지만 "사용자가 탄 열차"는 모르고, 폰은 탄 건 알지만 열차 번호를 모른다.
터널에서 GPS가 죽으므로 좌표 비교가 아니라 **탑승 순간에 identity를 한 번 잇는 방식**이어야 한다.

## 핵심 결정
- **위치 원천을 `realtimePosition`으로 교체** — 기존에 쓰던 도착정보 API는 한 열차가 여러 역에 동시에 나타나 위치로 쓸 수 없다. 위치 API는 열차당 한 줄이고 출발/도착 상태를 직접 준다
- **전 노선을 15초마다 상시 수집한다** — 실측해보니 원천이 60~90초마다만 갱신돼서 그보다 빨리 물어봐야 같은 값이다. 15초면 충분하고 그 정도 호출은 부담이 없다. 필요한 노선만 켜는 방식은 **버렸다** — 그러면 사용자가 승강장에 선 뒤에야 데이터를 모으기 시작해 2~3분간 아무 판단도 못 한다
- **출발은 "도착했다 → 출발했다"가 이어질 때만 인정** — 출발 표시 하나만 덜렁 보이면 낡은 데이터일 수 있다. 앞뒤가 맞으면 다음 역까지 기다리지 않고 확정한다
- **응답 시각을 사건 시각으로 믿지 않는다** — 그 값은 "최종수신시간"이고 실측상 현재보다 1~2분 뒤처져 있다. 시각을 점이 아니라 구간으로 다루고, 데이터가 빌수록 구간이 넓어져 판정이 저절로 보수적이 된다
- **다음 역 정차로 확정하는 쪽이 주력이다** — 관측 시간 해상도가 60~90초인데 러시아워 배차가 2분이라, 탑승 순간만 보고 열차를 특정하는 건 사실상 불가능하다. 일단 잠정으로 잡고 다음 역 정차 시각으로 가린다. 어느 후보와도 안 맞으면 확정하지 않는다
- **확정 전에는 하차 안내를 일절 안 낸다** — 앞차로 보이면 일찍 내리고 뒤차로 보이면 지나친다. 안전한 쪽이 없으므로 확정 전엔 "확인 중"만
- **고정 결과는 여정 단계 표가 아니라 1:1 별도 표에 둔다** — 단계 표는 재탐색마다 통째로 복제되는데, 복제에 열차 번호가 딸려가면 엉뚱한 열차가 계승된다. 표를 나누면 "복제 안 됨"이 기본이라 빠뜨려도 안전한 쪽으로 떨어진다

## 건드는 곳
`SeoulSubwayApiAdapter`+`SubwayApiPort`(위치 API 신설) · `SubwayLineIdMapper`(역매핑) ·
`SubwayDirectionNormalizer`·`RealtimeSubwayPositionCollector`·`SubwayTrainTransitionTracker`(신규) ·
`JourneyNavigationGeometryService` · `SubwayTrainMatcher`+`SubwayBindingMatchScheduler`(신규) ·
종료·정리 접점 4곳(`JourneyCommandService`·`JourneyLeaseExpiryService`·`JourneyStartTxService`·`RerouteAcceptTxService`) ·
`subway_leg_binding`(V44) · `subway_binding_event`(V45)

`journey_leg` 스키마는 **건드리지 않는다**. V43은 이미 쓰였으므로 착수 시 번호를 다시 확인해야 한다.

## 리스크
- **잘못 고정이 가장 비싼 실패** — 사용자가 엉뚱한 역에서 내린다. 애매하면 고정하지 않는 쪽으로 전부 기울여 놨고, 성공 지표도 "자동 고정 비율"이 아니라 오판율로 잡는다
- **관측이 실시간이 아니다** — 실측상 데이터가 1~2분 뒤처지고 60~90초마다만 갱신된다. 러시아워 배차와 같은 자릿수라 탑승 순간만으로는 열차를 못 가른다. 다음 역 정차 확인까지 "확인 중"이 길어지는 것을 받아들인 설계다
- **급행은 당분간 판정 대상에서 뺀다** — 급행이 어느 역을 통과하는지 알 데이터가 없다. 사용자가 급행을 타면 안내가 "확인 중"에 머문다. 감수하는 대신 잘못 고정은 막는다
- **V44·V45는 VPS 수동배치 필요** (V18+ untracked convention). 빠뜨리면 프로덕션이 깨진다

## 검증법
PR마다 컴파일 + 계약별 시험 통과. 특히 "출발 표시 하나만으로 확정 안 함", "꺼져 있으면 호출 0",
"후보 한 대여도 자동 확정 안 함", "미확정에서 하차 안내 안 나감", "사용자가 거부한 열차 재선택 안 함",
"옛 revision 재처리 안 함" 여섯 가드가 시험으로 고정돼야 완료.
운영 임계값은 실측 전까지 확정하지 않고 전부 설정값 + 기본 off.

외부 API 실측은 1회 끝냈다(폴링 주기·방향 값·지원 노선 확정). 남은 것은 수신 지연의 산포와 급행·지선 처리다.
