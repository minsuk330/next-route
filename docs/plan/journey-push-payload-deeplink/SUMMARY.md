# push payload 계약과 앱 진입 (Phase 5 ⑥, M)

## 뭘 하나

알림에 **deep link 와 문구 키**를 실어 보내고, 임시로 두었던 문구를 확정한다. payload 에는 여전히
식별자만 담는다. 마이그레이션 없음. 이 PR 도 운영 발송을 켜지 않는다 — 켜는 절차는 문서로만 정리.

## 왜

지금 알림을 누르면 앱이 어느 여정·어느 환승으로 가야 하는지 스스로 조립해야 한다. 문구도 "⑥이
정한다"고 적어 둔 임시 문장이라, 발송을 켜는 순간 그대로 굳는다.

## 핵심 결정

- **deep link 는 서버가 완성한 문자열**(`nextroute://journey/{id}?alertId=...&scope=...&scopeId=...`).
  앱 핸들러가 단순해지고 경로가 늘어도 서버만 고친다. https 유니버설 링크는 AASA·assetlinks 배포가
  선행되어야 해 지금은 못 쓴다
- **`notification` + `data` 를 계속 함께 보낸다.** 포그라운드 억제는 앱이 한다 — iOS 무음 push 는
  OS 가 미루거나 버려서 알림이 아예 안 뜨는 사례가 생긴다
- **문구는 서버가 갖고 `messageKey` 를 동봉한다.** 앱이 원하면 키로 자기 문구를 쓰고, 안 쓰면 서버
  문구가 보인다. 설정 키는 늘리지 않는다
- **`AT_RISK` 본문을 "서두르면 다음 차를 탈 수 있어요"로 바꾼다.** ④가 대기 중 `AT_RISK` 를 접근
  알림에 넘겨서, 이 문구가 나가는 상황은 아직 이동 중이다
- **알림 조회 API 를 만들지 않는다.** 기존 snapshot 이 대상 표시에 필요한 걸 이미 준다
- **payload 에 상태값을 넣지 않는다**(계약 유지). 30분 뒤에 연 알림의 숫자는 이미 틀렸다
