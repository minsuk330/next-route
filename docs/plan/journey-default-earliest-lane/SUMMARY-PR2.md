# 묶인 버스 대기 중 먼저 오는 노선으로 옮기기 (#614 PR-2) — 티어 L

## 뭘 하나
버스를 기다리는 단계이고 선택이 서버 기본(DEFAULT)이면, 평가 때마다 그 정류장 도착 정보(호출 1번에 전 노선)로 묶인 노선을 비교해
60초 이상 먼저 오는 노선으로 선택을 옮긴다. 대기·도착 예정·탑승 소요·환승 판정·알림이 함께 따라간다. 사용자가 고른 노선은 그대로.

## 왜
PR-1 은 검색 때 실시간만 본다. 늦게 시작해 차를 놓치거나 기다리는 동안 순서가 바뀌면 다시 틀린다. 두 번째 이후 버스 구간도 첫 노선 고정.

## 핵심 결정
- 재료 = 정류장 단위 도착(#577, Redis 캐시). 노선별 조회는 버스 공급자 슬롯을 십수 초 잡고 경기 일일 한도(5000)를 대기 30번이면 소진 → 기각.
- 안 옮기는 경우: 60초 미만 차이, 조회 실패·막힘, 지금 선택 버스가 도착 중·막 떠남(탔는데 탑승 전이 전), USER.
- 저장은 평가기 소유권 확인 뒤 같은 트랜잭션에서 "선택 그대로·DEFAULT·대기 중" 재확인 후. 어긋나면 그 대기 결과 버림.
- 옮길 때 옛 노선 "곧 도착" 대기 알림 취소, 재탐색 보드 갱신, 평가 번호 +1. 마이그레이션 없음.
- 사용자 확인(DEFAULT→USER)도 평가를 당겨 도중 결과가 저장되지 않게(PR-1 경로 보강).

## 건드는 곳
MergedBusLaneChooser(신규), TransferRiskEvaluator, TransferTargetArrivalService(선택 덮어쓰기), TransferAssessmentBatch, JourneyEvaluationService(grace·stabilize),
JourneyEvaluationScheduleWriter(finish 순서), 접근 알림 취소, BusRouteSelectionService

## 리스크
- 정류장 도착 행 ↔ 후보 대조를 노선 번호로 함 — 같은 번호 다른 노선(지역 중복)이면 오대조 가능. 못 맞추면 그 후보 제외.
- 앱 대기 화면 규칙과 60초 이력이 다르면 잠깐 다른 노선을 보일 수 있음.
- 평가기 저장 경로 변경이라 회귀 범위가 넓음(알림·예측 저장).

## 검증법
고르기 단위 시험(60초 경계, 도착 중 창, 실패 시 유지), 평가 IT(옮김 적용·평가 번호·새 예측 유지·알림 노선 이름·접근 알림 취소, USER 유지,
확인 경로가 평가 도중 끼면 결과 버림), 전체 시험.
