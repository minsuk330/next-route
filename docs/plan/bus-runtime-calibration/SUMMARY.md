# 버스 GTFS 탑승 시간 실측 보정

## 뭘 하나
그래프를 빌드하기 전에 버스 시간표(stop_times)의 정류장 사이 주행 시간을 실측 계수만큼 늘린다. 서울부터 노선×시간대 계수로 하고, 경기·인천·지방은 데이터를 모은 뒤 단계적으로 한다.

## 왜
OTP 버스 시간은 KTDB 추정 시간표 그대로다. 서울 실측(208개 노선)보다 약 42% 짧다(실측 = GTFS × 1.74, 421 강남→서울역 실측 38~44분 vs 24분). 그래서 버스가 지하철보다 앞에 서고, ETA·알림 시각도 앞당겨진다.

## 핵심 결정
- 빌드 전 전처리로 보정한다. 기각: OTP 런타임(배율 기능 없음), GTFS-RT(정적 원칙 위반·차량 키 없음)
- 지역별로 계수를 따로 쓴다. 기각: 전국 단일 계수(부산은 오히려 느림 0.68, ODsay 와 같음 1.01)
- 서울 계수 원천은 TOPIS OA-21217(구간 평균 운행 시간, 1시간 단위)이고, 우리 실측은 검증 세트로 쓴다
- 첫 정류장 출발 시각(배차·첫막차)은 보존하고, 같은 패턴 추월 가드를 둔다
- 보정 뒤 버스 reluctance 1.3 을 코퍼스로 다시 고른다

## 건드는 곳
tools/transit-routing-benchmark/runner/calibrate_bus_runtimes.py(신규)+테스트, build_otp_graph.sh, 계수표, release-manifest, 운영 그래프, (필요 시) OtpRoutingProperties.busReluctance

## 리스크
- 버스 경로 ETA·알림 시각이 전반적으로 늦어진다(의도) — 알림 회귀 확인 필요
- 보정 안 한 지역(경기·지방)과 서울 사이 순위 불균형 → reluctance 를 지역 구분 없이 낮추면 지방 버스가 과대 노출될 수 있다
- OA-21217 형식·정차 포함 여부 미확인

## 검증법
서울 실측 평가 세트(기간 분리)에서 LONG 오차 중앙값 42.6% → 12% 이하. 코퍼스에서 강남→서울역 지하철 1위, 버스가 맞는 구간은 버스 1위 유지.
