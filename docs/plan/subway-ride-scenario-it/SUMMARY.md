# 지하철 탑승 열차 고정·진행 링 — 사용자 시나리오 통합 테스트

## 뭘 하나
위치 응답 → 전이 추적 → 출발 색인 → 탑승 열차 고정 → 진행 링 → 잠금화면 push 까지를 실제 DB·Redis 위에서 한 번에 돌리는 IT 를 만든다. 사용자 이야기 9개(출근길 확정, 링·잠금화면, "이 열차 아님", 한산한 시간대 후보 하나, 도착목록 누락, 실시간 끊김, 중복 행, 위치 수집 없음, 여정 종료).

## 왜
기존 IT 는 부품 하나씩만 보고 이웃을 mock 으로 막아, 사슬이 실제로 이어지는지는 한 번도 검증된 적이 없다.

## 핵심 결정
- 가짜는 바깥 경계(서울 API 두 개·FCM·검색 스냅샷·시계)에만 — 안쪽은 전부 진짜
- 수집기 대신 추적기에 직접 입력 — 수집기는 벽시계로 운행시간을 봐서 새벽에 시험이 흔들린다
- 스케줄러 대신 tick 직접 호출 + 가변 시계 — 결정적 재현
- 위치·도착 피드는 한 "세계 표"에서 함께 생성 — 두 피드가 서로 모순되지 않게
- 버그가 나오면 이 PR 에서 안 고침 — 노트 기록 후 별도 PR
