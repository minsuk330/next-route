# 지하철 급행 표시·추적

## 뭘 하나
경로·도착판·열차 고르기·안내 화면에서 열차마다 급행인지 보여 주고, 급행을 골라 타도 링·Dynamic Island 가 그 열차의 정차역 기준으로 따라간다. 경로 검색은 급행·일반을 둘 다 보여 주고 급행 끄기 옵션을 둔다. 낡은 OTP 지하철 데이터는 수동 보정한다.

## 왜
지금은 급행 표시가 없고, 급행을 고르면 지나치는 역을 다음 역으로 세다 하차역을 지나도 '도착'으로 처리된다. OTP 시간표도 11-30 에 끝난다.

## 핵심 결정
- 급행 정답은 저장소의 급행 표 12계통(웹 최신 자료·실측, 출처·시행일 포함). OTP·국토부 파일은 정답으로 안 씀
- 급행 판정: 실시간은 열차별 trainType/directAt, 경로는 노선 이름 또는 정차 패턴 비교. 직통·ITX 는 추적 제외
- 급행 탑승 시 역 개수·다음 역은 그 열차가 서는 역만 셈. 통과역 신호는 진행 근거로만 씀
- 서지 않는 급행은 흐리게 보이되 고를 수 없음. 급행 끄기로 0건이면 필터를 풀고 "급행 포함 결과" 안내
- OTP 보정·시간표 연장(PR-G1)과 급행 기능을 지금 함께 진행, 배포만 G1 먼저(11-30 만료)

## 건드는 곳
OTP GTFS 보정 도구, express-catalog.json, 경로 검색(OTP 질의·매퍼·분류기·랭커·응답), 여정 단계(V71), 열차 고르기·도착판·하차역 고르기, 바인딩(V72)·링 체인·신호·구간 시간, 재탐색 옵션(V73), jette-app 경로·안내·열차 고르기·Live Activity

## 리스크
- 통과역 신호 해석(도착 코드 4·5)은 가정 → 실제 급행 탑승 녹화로 검증 전까지 급행 추적 플래그 off(그동안 급행은 '추적 불가'로 선택만 막음)
- 수인분당·경의중앙처럼 같은 노선 안의 급행은 OTP 가 노선 단위로만 걸러 일반 대안을 보장 못 함
- KTDB 에 열차번호가 없어 경로 검색의 열차별 예외(금천구청·의왕 등)는 패턴 기준 근사
- 같은 노선 급행·일반 쌍이 경로 10칸 중 2칸을 써 버스 대안이 밀릴 수 있음

## 검증법
마곡나루→신논현·선릉→수원 검색에 급행 배지와 일반 대안, 급행 끄기 동작. 9호선·1호선 경부 급행 실제 탑승 녹화 재생에서 남은 역·다음 역이 정차역 기준이고 통과역 오판 없음. 서버 전체 테스트·IT 통과.
