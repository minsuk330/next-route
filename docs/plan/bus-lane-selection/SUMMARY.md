# 버스 묶음 처리: 노선별 시간과 고른 버스로 여정 시작

## 뭘 하나
묶인 버스 노선마다 탑승시간을 내려주고, 환승 대기 계산이 실제로 타는 노선의 시간을 쓰게 한다.
버스에 탈 때 사용자가 고른 노선을 받아 그 노선 기준으로 추적한다.

## 왜
지금은 묶음의 첫 노선 시간만 쓰고 첫 노선으로만 추적한다. 다른 묶인 버스를 타면 환승 판정이 최대 9분 어긋나고 내비가 틀린 노선을 따라간다.

## 핵심 결정
- 응답 `lanes[]` 에 `rideSeconds` 칸 추가(기존 칸 그대로). 기준만 조이는 안은 오차가 남아 기각.
- 탑승 시점에 탄 노선을 받는다(탑승 이벤트에 노선 선택 추가, 계약은 PR-2 착수 때 확정). 그 전까지는 첫 노선.
- 고른 노선의 정류장 목록과 선은 시작할 때 OTP 에서 다시 받는다. 검색 응답에 전부 싣는 안은 응답이 커져 보류.
- 묶음 허용 기준(1.3배 + 5분)은 이번에 안 바꾼다. PR-1 뒤 다시 본다(#599).
- PR: ①노선별 시간 + 환승 대기(이 PR) ②탑승 때 고른 노선으로 추적 전환.

## 건드는 곳
LaneResult, LegacyRouteResponseMapper, TransferArrivalEnricher, RouteSearchTravelTimeEstimator, StartJourneyRequest, JourneyCompiler, JourneyStartTxService, journey_leg_route_option(컬럼 추가), 앱(jette-app#127, #123)

## 리스크
- 여정 시작에 OTP 조회가 하나 늘어난다(지연, 실패 시 대표 값으로 폴백).
- 묶음에 다른 지역 노선이 섞이면 고른 노선의 실시간 도착 정보가 없을 수 있다.
- 검색 스냅샷에 저장된 옛 형식과의 호환을 테스트로 고정해야 한다.

## 검증법
계약마다 테스트(노선별 시간, 환승 대기가 타는 노선 기준, 선택대로 시작, 잘못된 선택 400, 생략 시 기존 동작).
운영 OTP 로 버스→버스 환승 경로의 환승 도착 시각이 타는 노선 기준으로 바뀌는지 확인.
