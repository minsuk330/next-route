## 뭘 하나

②③④가 만든 것은 전부 **제안**이라 아직 아무 여정도 안 바뀌었다. ⑤는 사용자가 고른 제안 하나를
받아 **실제로 안내 경로를 갈아끼운다.** 개정본·단계·노선 후보·환승·지도 geometry 다섯이 한
트랜잭션에서 함께 움직인다.

## 왜

사다리의 마지막 실행 칸이다. ⑤가 없으면 사용자는 "이 길이 5분 빠릅니다"를 보기만 하고 **누를 수
없다.** 그리고 Phase 5 가 미리 넣어 둔 `route-changed` 알림 취소가 **처음으로 실제 동작하는 자리**다.

## 핵심 결정

- **새 개정본은 전체 단계를 복제한다.** 남은 구간만 넣으면 여정 조회가 개정본 하나의 단계 전부를
  읽기 때문에 사용자 화면에서 **지나온 길이 통째로 사라진다.** 앞 구간은 재컴파일이 아니라
  **값 복제**다 — 진행도·증거를 잃으면 앱의 GPS 엔진이 진행 중인 단계를 처음부터 다시 센다
- **개정본 스냅샷을 합성한다** — 옛 스냅샷의 앞 구간 + 후보 경로. 후보 경로만 저장하면 단계 번호와
  원본 구간 번호가 어긋나 **지도가 오류 없이 조용히 틀린다.** ④의 좌표 찾기도 같이 틀린다
- **geometry 원천을 세션 스냅샷 → 지금 개정본 스냅샷으로 옮긴다.** 세션 쪽은 시작 시점 원본이라
  영원히 안 바뀐다. 안 옮기면 수락해도 지도에 옛 경로가 계속 내려간다 — **이게 ⑤의 숨은 절반**이라
  선행 PR 로 뗀다
- **지금 진행 중인 단계 규칙**(PHASE-6 이 비워 둔 항목): 교체 시작점을 **지났으면 409**, 같으면
  적용하고 `ACTIVE` 상태를 잇는다. 버스에 타고 있는 중이면 하차 지점부터 새 경로다
- **낙관적 락 세 겹** — 제안 상태 조건부 update(중복 수락) · `commandVersion`(사용자가 움직였다) ·
  `routeRevision`(경로가 이미 바뀌었다). 하나로 줄이면 나머지 둘이 조용히 통과한다
- 같은 후보로 다시 누르면 **200 + 최신 스냅샷**(재전송), 다른 후보면 409

## 리스크

- **합성 스냅샷이 유일한 외줄.** "다시 쪼개면 저장된 단계가 나온다"가 깨지면 지도와 ④가 함께
  틀리는데 **오류는 안 난다.** 시험으로 못 박는다
- **앞 구간 복제에서 칸 하나를 빠뜨려도 시험이 통과한다** — 대부분 다음 평가가 다시 채우기 때문이다.
  그래서 복제 시험은 값 비교가 아니라 **칸 목록을 세는** 방식으로 짠다
- **PR-1 은 이미 화면이 쓰고 있는 코드를 건드린다.** 1번 개정본에서 두 스냅샷이 같은 값이라는
  것으로 회귀를 막고, 기존 geometry 시험이 무수정 통과해야 한다
- 조건부 update 를 통과한 뒤 뒤늦게 거절하면 **제안만 소모되고 여정은 그대로**인 상태가 남는다.
  거절은 트랜잭션 롤백으로 처리한다

## 검증법

수락 한 번에 `routeRevision`·`commandVersion` 이 각각 1씩 오르고, 새 개정본에 **앞 구간이 그대로**
있고, 새 스냅샷을 다시 쪼갠 결과가 저장된 단계와 일치한다. 동시 수락은 한 번만 성공하고 재전송은
개정본을 한 번만 올린다. 이전 개정본의 알림이 취소된다. 둘 다 `./gradlew build` 전체 통과.
