# 파이프라인 4단계: 수정 코드 제안

## 뭘 하나
원인 분석 뒤 조건을 통과한 알림에 한해 LLM 이 찾아 바꾸기 블록으로 수정 코드를 만들고, 배포 커밋과 main 에서 원문을 대조해 Slack 스레드 두 번째 답글로 diff 를 보여 준다. PR 은 만들지 않는다.

## 왜
3단계는 고칠 곳까지만 짚는다. 다음 단계(영향 범위, 관련 테스트, 승인)에 넘길 실제 수정안이 필요하다.

## 핵심 결정
- 조건: app_bug + 확신도 high/medium + 고칠 곳 후보에 s: 근거(low·외부 장애·카드만은 제외)
- 형식: 찾아 바꾸기 블록(시험: 적용 18 대 16, 고친 위치 16 대 13 / unified diff 기각)
- 배포 커밋과 main 둘 다에서 대조: 둘 다 맞으면 제안, main 에서 바뀌었으면 "이미 고쳐졌는지 확인", 배포 코드에도 없으면 버림
- 결과는 Slack 미리보기만, 분석기 GitHub 권한은 읽기 그대로(쓰기는 7단계)
- 분석과 별도 LLM 호출, 조건 미달이면 비용 0

## 건드는 곳
alert-analyzer(config, code, fix, llm, slack, worker, app, prompts/fix.md, eval/fix_format.py, tests)

## 리스크
- 조건이 좁아 실알림에서 한동안 안 돌 수 있음(skipped 횟수 기록)
- 적용은 되지만 엉뚱한 수정 가능(시험 2/18) → "참고용" 표시, 5~7단계가 거름

## 검증법
pytest 전부 통과(조건, 대조 ①②③, 실패 경로, Slack 길이). 운영 컨테이너에서 연습 맥락으로 제안 1회 생성해 상태와 diff 확인.
